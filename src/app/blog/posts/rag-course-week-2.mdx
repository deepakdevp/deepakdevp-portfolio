## The RAG Architecture (Quick Recap)

Before diving into Week 2, here's the basic RAG flow:

1. **Index time**: Split documents → Generate embeddings → Store in vector DB
2. **Query time**: User asks question → Embed question → Search vector DB → Get relevant docs → Feed to LLM → Generate answer

Simple in theory. Week 2 was about making it work in practice.

## Part 1: Understanding Embeddings

The course started with embeddings, which I thought I understood. I was wrong.

**What I thought**: Embeddings are just vectors that represent text.

**What I learned**: Embeddings are *semantic* vectors where **similar meanings are close in high-dimensional space**, even if the words are completely different.

Claude Code helped me internalize this with a practical example:

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')

sentences = [
    "The server crashed and is showing error 500",
    "Internal server error when accessing the API",
    "How do I deploy the frontend?",
    "The deployment pipeline failed"
]

embeddings = model.encode(sentences)

# Calculate cosine similarity
from sklearn.metrics.pairwise import cosine_similarity
similarities = cosine_similarity(embeddings)

print(similarities)
```

Output:
```
[[1.00, 0.87, 0.23, 0.31],  # "server crashed" vs others
 [0.87, 1.00, 0.19, 0.28],  # "internal server error" vs others
 [0.23, 0.19, 1.00, 0.76],  # "deploy frontend" vs others
 [0.31, 0.28, 0.76, 1.00]]  # "deployment failed" vs others
```

**Mind blown.** Sentences 1 and 2 use completely different words but have 87% similarity because they mean the same thing. Sentences 3 and 4 cluster together because they're both about deployment.

This clicked for me when Claude pointed out: "That's why RAG works better than keyword search—it understands *intent*, not just words."

## Part 2: Choosing an Embedding Model

The course covered several embedding models:

- **OpenAI text-embedding-ada-002**: Proprietary, expensive, very good
- **Sentence-Transformers (open source)**: Fast, free, good enough for most use cases
- **Instructor models**: Fine-tuned for specific retrieval tasks
- **E5 models**: State-of-the-art open source

I tested three models on our internal docs:

```python
models = [
    'all-MiniLM-L6-v2',           # Fast, 384 dims
    'all-mpnet-base-v2',          # Better quality, 768 dims  
    'BAAI/bge-small-en-v1.5',     # Current best open-source
]

# Test query: "How do I configure Redis caching?"
# Ground truth: Should retrieve our Redis setup guide

for model_name in models:
    model = SentenceTransformer(model_name)
    # ... test retrieval quality ...
```

Results:
- **MiniLM**: Fast (10ms), found the Redis doc but also pulled in irrelevant cache docs
- **mpnet**: Slower (25ms), much better relevance
- **BGE**: Best results (30ms), worth the extra time

**Lesson learned**: Start with mpnet or BGE for better quality. Only optimize to MiniLM if speed becomes an issue.

## Part 3: Setting Up a Vector Database

This was the most practical part of Week 2. The course covered four vector databases:

1. **Chroma** - Simple, local, great for prototypes
2. **Pinecone** - Hosted, easy, but paid
3. **Weaviate** - Open source, powerful, steeper learning curve
4. **Qdrant** - Rust-based, fast, good balance

I chose **Chroma** for the prototype because setup was literally three lines:

```python
import chromadb
from chromadb.config import Settings

client = chromadb.Client(Settings(
    chroma_db_impl="duckdb+parquet",
    persist_directory="./chroma_db"
))

collection = client.create_collection("engineering_docs")
```

Done. No servers, no config files, just works.

## Part 4: Building the Indexing Pipeline

Here's where I actually built something. The goal: index all our internal engineering docs (Markdown files in a Git repo) so we can search them semantically.

### Step 1: Load Documents

```python
import os
from pathlib import Path

def load_docs(docs_path):
    docs = []
    for file_path in Path(docs_path).rglob("*.md"):
        with open(file_path, 'r') as f:
            content = f.read()
            docs.append({
                'content': content,
                'source': str(file_path),
                'title': file_path.stem
            })
    return docs

docs = load_docs("./engineering-docs")
print(f"Loaded {len(docs)} documents")
```

Result: 147 markdown files loaded.

### Step 2: Chunk Documents

This is where Week 1's chunking strategies came in handy. I used semantic chunking with a 500-token overlap:

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    separators=["\n\n", "\n", ". ", " ", ""]
)

chunks = []
for doc in docs:
    doc_chunks = text_splitter.split_text(doc['content'])
    for i, chunk in enumerate(doc_chunks):
        chunks.append({
            'text': chunk,
            'source': doc['source'],
            'chunk_id': f"{doc['title']}_chunk_{i}"
        })

print(f"Created {len(chunks)} chunks from {len(docs)} documents")
```

Result: 147 docs → 892 chunks.

Claude Code suggested adding metadata to chunks:

```python
# Enhanced version with metadata
for doc in docs:
    doc_chunks = text_splitter.split_text(doc['content'])
    for i, chunk in enumerate(doc_chunks):
        chunks.append({
            'text': chunk,
            'metadata': {
                'source': doc['source'],
                'title': doc['title'],
                'chunk_index': i,
                'total_chunks': len(doc_chunks),
                'doc_type': 'engineering_doc'
            }
        })
```

This metadata became super useful later for filtering results.

### Step 3: Generate Embeddings

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-mpnet-base-v2')

# Batch encoding for efficiency
texts = [chunk['text'] for chunk in chunks]
embeddings = model.encode(texts, show_progress_bar=True, batch_size=32)

print(f"Generated {len(embeddings)} embeddings of dimension {embeddings.shape[1]}")
```

This took about 2 minutes for 892 chunks. Not bad.

### Step 4: Store in Vector DB

```python
collection.add(
    embeddings=embeddings.tolist(),
    documents=texts,
    metadatas=[chunk['metadata'] for chunk in chunks],
    ids=[chunk['metadata']['chunk_id'] for chunk in chunks]
)

print("✅ Documents indexed successfully!")
```

**Done!** The entire indexing pipeline ran in about 3 minutes.

## Part 5: Building the Query Pipeline

Now for the fun part—actually searching and answering questions.

```python
def search(query, n_results=5):
    # Embed the query
    query_embedding = model.encode([query])[0]
    
    # Search vector DB
    results = collection.query(
        query_embeddings=[query_embedding.tolist()],
        n_results=n_results
    )
    
    return results

# Test it
results = search("How do I configure Redis caching?")
for doc, metadata in zip(results['documents'][0], results['metadatas'][0]):
    print(f"Source: {metadata['source']}")
    print(f"Content: {doc[:200]}...")
    print("---")
```

**It worked!** The top result was exactly our Redis configuration guide.

## Part 6: Adding the LLM

The final step: use retrieved context to generate answers.

```python
from openai import OpenAI

client = OpenAI()

def answer_question(query):
    # 1. Retrieve relevant docs
    results = search(query, n_results=3)
    context = "\n\n".join(results['documents'][0])
    
    # 2. Build prompt
    prompt = f"""Answer the question based on the following context.

Context:
{context}

Question: {query}

Answer:"""
    
    # 3. Generate answer
    response = client.chat.completions.create(
        model="gpt-4",
        messages=[
            {"role": "system", "content": "You are a helpful engineering assistant. Answer based on the provided context."},
            {"role": "user", "content": prompt}
        ],
        temperature=0
    )
    
    return response.choices[0].message.content

# Test it
answer = answer_question("How do I configure Redis caching?")
print(answer)
```

Output:
```
To configure Redis caching, follow these steps:

1. Install the Redis client: `pip install redis`
2. Set up the connection in config.py:
   - REDIS_HOST = 'localhost'
   - REDIS_PORT = 6379
   - REDIS_TTL = 3600

3. Use the cache decorator for functions:
   @cache.cached(timeout=REDIS_TTL)
   def expensive_operation():
       # ...

For production, use environment variables and enable SSL.
```

**Perfect.** It pulled the relevant info from our docs and generated a clear answer.

## What I Learned

1. **Embeddings are the secret sauce** - Quality embeddings matter way more than fancy retrieval algorithms
2. **Chunking strategy impacts results** - Too big = irrelevant context, too small = missing context
3. **Metadata is underrated** - Source attribution and filtering are essential for production
4. **Start simple** - Chroma + Sentence-Transformers is good enough for most use cases
5. **Test with real queries** - Synthetic benchmarks don't capture actual usage patterns
